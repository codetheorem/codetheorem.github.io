I'm Hrishikesh Agarwal, a software engineer based in Bengaluru. My professional work is in AI infrastructure and agentic systems. My independent interests extend into LLM inference, distributed systems, database internals, and philosophy.

The common thread is a wish to understand what an abstraction costs and what it promises. A model call hides computation. A database write hides a durability contract. An agent hides a chain of decisions. I want to be able to reason about the machinery underneath.

## Education and the first shared codebases

I studied Computer Science Engineering at Shri Mata Vaishno Devi University in Katra, graduating in 2023. During Google Summer of Code in 2022, I worked with the Python Software Foundation's SUSE EOS organization on JavaScript product features, including tracking and community-management functionality.

Contributing to a shared project made the work larger than an isolated implementation. Someone else had to understand a change, maintain it, and use it within an existing system.

## Application engineering at Tata Elxsi

At Tata Elxsi, my work crossed software automation and generative AI. I built tools for unit-test generation, UML generation from specifications, document retrieval, and cloud cost governance. The stack included Python, language-model APIs, retrieval pipelines, and agent frameworks.

These applications kept raising questions that were more about systems than prompting: where state lives, how a workflow resumes, how a tool failure propagates, and how to tell whether an apparently good response actually completed the task.

## Agentic systems and infrastructure at Sasken

At Sasken Technologies, I work on agentic systems including predictive maintenance and conversational commerce. I also built [Tokenomics](/projects/tokenomics/), an internal LLM optimization gateway.

Tokenomics brought model routing, context handling, caching strategies, escalation, and measurement into the same problem. The relevant cost was the cost of completing a task, including failed attempts and optimization overhead. The [public engineering account](/blog/how-i-built-tokenomics/) explains the principles without disclosing proprietary implementation details or internal benchmarks.

## Independent directions

[FerrumLM](/projects/ferrumlm/) and [FerrumData](/projects/ferrumdata/) are research directions for studying inference and analytical execution through Rust. They are scopes for investigation, not completed engines. [FerrumDB](/projects/ferrumdb/) is a future embedded-database plan.

[DesignBrew](/projects/designbrew/) is an independent creative-production prototype. It explores editable artifacts, revision, and provenance: the systems around generation rather than generation alone.
